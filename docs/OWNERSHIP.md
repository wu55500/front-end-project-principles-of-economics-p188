## 2. 不依赖任何人，自己看线上效果

- 直接用浏览器打开：`http://139.155.132.81`
- 该地址 24 小时运行在自己的腾讯云服务器上，与任何协作者的电脑是否开机无关。
- **如果用手机移动流量打不开（ERR_CONNECTION_RESET / TIMED_OUT）**：这是运营商对
  “80 端口 + 未备案裸 IP”的 HTTP 拦截，不是服务器故障。
  - 立即验证：改用 **WiFi**（电信/联通最佳）打开；
  - 用移动流量：让运维在服务器与腾讯云安全组放行一个高位端口（如 8088），访问 `http://139.155.132.81:8088`；
  - 一劳永逸：注册域名 → 实名 → **ICP 备案** → 配置 HTTPS（443）。备案后三大运营商均不再拦截。
- 判断“是网络问题还是服务器问题”：换 WiFi/换网络能开，即说明服务器正常、是原网络拦截。

## 3. 一键收回所有第三方（含 AI）访问权

做完下面两步，除主人外任何人/AI 都无法再访问代码与服务器：

1. **收回服务器**：腾讯云控制台 → 云服务器 CVM → 选中实例 → 「更多 / 重置密码」，
   设置新 root 密码（不需要旧密码）。所有曾被缓存的旧密码立即失效。
   - 建议同时检查：控制台「密钥对」里删除不认识的 SSH 公钥。
2. **收回 GitHub**：GitHub 网页 → Settings → Developer settings → Personal access tokens，
   撤销不认识的 token；最彻底的方式是直接修改 GitHub 账号密码（会使全部 token 失效）。
   - 仓库 Settings → Collaborators 里确认没有多余协作者。

> 网站在 Docker 容器里继续运行，改密码/撤 token 不影响线上，只是断了外部访问通道。

## 4. 自己重新部署（换电脑/换服务器也能起）

仓库内已具备完整可复现部署材料：

- `Dockerfile`：多阶段构建，非 root 运行，最终服务监听容器内 8080；
- `deploy/nginx/`：生产真实 Nginx 配置（反向代理、安全头、限流、敏感路径 404），含安装命令；
- `DEPLOYMENT.md`：完整上线步骤。

简要流程：拿到一台装了 Docker 的 Linux 服务器 → 拉取仓库 →
`docker build -t p188-econ .` → 运行容器映射到本机 8080 → 用 `deploy/nginx/` 配置 Nginx 反代 80→8080。
